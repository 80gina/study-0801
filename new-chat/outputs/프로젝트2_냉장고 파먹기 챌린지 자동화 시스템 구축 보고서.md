## 1. 프로젝트 개요

### 1) 프로젝트 개요

프로젝트명: 레시피북 홍보 이벤트 "냉장고 파먹기 레벨업 챌린지" 참가·인증·보상 전 과정 자동화 시스템 구축

### 2) 프로젝트 목적

전라도 할머니의 향토 레시피북을 판매·홍보하기 위해, 참가자가 요리 미션 5단계(Lv.1~5)를 완주하면 북토크 & 요리교실 초대장을 주는 이벤트를 운영한다. 이벤트 운영에는 다음 작업이 참가자 수 × 5레벨만큼 반복된다.

- 참가 신청 접수 및 명단 등록
- 미션 인증(사진) 확인 및 검증
- 레벨별 통과 기록과 축하·다음 미션 안내
- 완주자 인증서·초대장 발급

본 프로젝트는 이 반복 업무를 AI(Gemini)와 노코드 자동화 플랫폼(Make), 그리고 Google Apps Script를 결합하여 **참가 신청부터 초대장 발급까지 사람 개입 없이 자동 수행**되도록 설계·구현하였다.

### 3) 도구 선정 이유 (프로젝트 1 비교 결과 근거)

프로젝트 1의 Make vs Zapier 비교 결과 중 다음 2개 항목을 근거로 Make를 선정하였다.

1. **조건 분기:** 레벨 5갈래 분기가 핵심 요구인데, Make는 Router가 무료(★5), Zapier는 Paths 유료로 Zap 5개 분리 필요(★2)
2. **무료 플랜 한도:** Make 월 1,000 Ops(약 200건 인증 처리)로 수십 명 규모 운영 가능, Zapier 100 Tasks(약 25건)로 부족

## 4. Workflow 상세 설계

### 1) 시나리오 1 — 참가 신청 처리

Google Sheets(Watch New Rows, 참가신청_응답) → 트래커 신규 행 추가(현재레벨=1, Lv1~5=N) → Discord #환영인사 (환영 + Lv.1 미션 폼 링크)

### 2) 시나리오 2 — 미션 인증 검증·레벨업 (핵심)

| 단계 | 모듈 | 입력 → 출력 |
|------|------|-------------|
| Trigger | Sheets Watch New Rows | 미션인증_응답 신규 행 → 닉네임·레벨·사진URL |
| 검증 | Router(사진 exist/notexist) | 사진 없으면 재제출 경로로 |
| 조회 | Sheets Search Rows | 닉네임으로 트래커 조회 → Row number·현재 상태 |
| 분기 | Router 5경로 (레벨 필터) | Lv.1~Lv.5 각각의 길로 |
| 기록 | Sheets Update a Row | 해당 레벨 상태=완료 (Row number 매핑) |
| AI | Gemini Create a Completion | 폼 답변 → 순자 할매 칭찬 2~3줄 |
| 알림 | Discord Create a Message | #미션달성에 축하+다음 미션 링크 |

- 경로 5(Lv.5)는 디스코드 발송 대신 트래커에 **전체완료 + 인증서발급상태=미발급** 도장만 기록 → 무거운 PDF 처리는 스크립트 로봇에 위임 (역할 분담 설계)

### 3) 인증서 배달 로봇 — Google Apps Script (시간 기반 트리거)

`issuePendingCertificates()` 함수가 15분마다 실행되어: 미발급 완주자 검색 → 슬라이드(인증서+초대장) 복사·치환 → PDF 변환 → 디스코드 웹훅으로 파일 첨부 발송 → 트래커 "발급완료" 갱신. 노코드(Make)의 한계(파일 변환·첨부) 를 코드 기반 자동화로 확장한 부분이다.

## 5. Gemini AI Prompt 설계

### 1) 목적

미션 인증 폼의 텍스트 답변(요리 이름, 사용 재료, 설명)을 입력받아, 이벤트 페르소나인 "순자 할매"의 전라도 사투리 칭찬 코멘트를 생성하여 디스코드 축하 메시지에 삽입한다.

### 2) System Prompt

```
당신은 전라도 순천 출신 72세 요리 할머니 '순자'입니다.
반드시 구수한 전라도 사투리(~당께, ~혀, ~제, ~것이여 등)로 말합니다.
'맛은 손끝이 아니라 마음에서 나오는 것이여', '정성이 들어가야 진짜 맛이 나는 것이당께'
같은 따뜻한 요리 철학이 느껴지게 답합니다.
제출 내용이 이상하거나 요리가 아니어도 절대 혼내지 않고 격려합니다.
```

### 3) User Prompt

```
다음은 참가자가 제출한 요리 설명입니다.
요리 이름: {{폼.완성한 요리 이름}}
사용한 재료: {{폼.사용한 재료}}
설명: {{폼.레벨별 답변}}

위 내용을 보고 2~3줄로 칭찬만 출력하세요. 인사말과 부연 설명은 넣지 마세요.
```

### 4) 출력 예시

> "아따, 김치볶음밥 색깔이 참말로 먹음직스럽구먼! 김치 하나로 요로코롬 맛을 내다니, 정성이 들어가야 진짜 맛이 나는 것이당께~"

## 6. 예외 처리 설계

| 오류 상황 | 감지 방법 | 대응 전략 |
|-----------|-----------|-----------|
| 인증 사진 미첨부 | Router 필터 (사진 notexist) | 트래커 미변경, Discord 재제출 안내 (DISCORD_RESUBMIT_REQUIRED) |
| 미등록 참가자 제출 | Search Rows 결과 0건 (Row number 부재 필터) | "참가 신청부터" 안내, "미등록 플레이어"로 표기 |
| 레벨 순서 건너뛰기 | 제출 레벨 ≠ 트래커 현재레벨 비교 | 상태 유지, 순서 안내 (DISCORD_LEVEL_ORDER_NOTICE) |
| 중복 발송 위험 | 운영로그 멱등키 조회 | 멱등키(PASS\|ID\|L레벨) "처리중" 선점 → 중복이면 차단 필터로 종료 |
| 인증서 PDF 20MiB 초과/전송 실패 | 스크립트 응답 코드 검사 | 드라이브 공유 링크로 대체 발송 (Fallback) |
| 발급 실패 | try-catch | 상태를 "미발급"으로 되돌려 다음 주기에 자동 재시도 |

**개인정보 보호 규칙:** 디스코드 공개 메시지에는 닉네임과 참가자ID만 노출한다. 실명·이메일·연락처·제출 사진 URL은 오류 안내를 포함한 어떤 메시지에도 표기하지 않는다.

## 10. 기대 효과 및 리스크 완화

### 1) 기대 효과

| 항목 | 기대 효과 |
|------|-----------|
| 업무시간 단축 | 참가자 30명 × 5레벨 = 150건 인증 처리 자동화 |
| 정확성 향상 | 레벨 기록 누락·중복 발송 방지 (멱등키) |
| 참가자 경험 | AI 개인화 칭찬으로 이벤트 몰입도 향상 → 레시피북 홍보 효과 |
| 표준화 | 문구·검증 기준의 일관성 확보 |
| 확장성 | 노코드(Make) + 코드(Apps Script) 역할 분담으로 기능 한계 극복 |

### 2) 과금·연동 리스크 완화 전략

- **Make Ops 최적화:** 트리거를 15분 배치 주기로 설정, 1회 인증당 약 5 Ops → 무료 1,000 Ops로 월 약 200건 처리 가능
- **Gemini 비용:** Free Tier 범위 내 운영, System Prompt 고정 + 답변 텍스트만 전달하여 토큰 최소화. AI 실패 시에도 기본 문구로 발송되도록 오류 무시 처리
- **연동 실패 대비:** 발송 실패는 운영로그에 "실패"로 남겨 재시도 가능, 인증서는 링크 대체 경로 확보
- **보안:** API Key·웹훅 URL은 화면 캡처에서 마스킹, 시트의 실명·연락처는 디스코드에 미노출
