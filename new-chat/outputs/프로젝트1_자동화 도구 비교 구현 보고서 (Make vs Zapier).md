## 1. 프로젝트 개요

### 1) 프로젝트 개요

전라도 할머니 레시피북 홍보 이벤트 "냉장고 파먹기 레벨업 챌린지"의 미션 인증 처리 업무를 자동화한다. 참가자가 구글 폼으로 요리 미션(Lv.1~5)을 인증하면, 사진 첨부 여부를 검증하고 레벨별로 분기하여 트래커 시트에 기록한 뒤, AI(Gemini)가 생성한 "순자 할매 칭찬 코멘트"와 함께 디스코드로 축하 메시지를 발송한다.

### 2) 구현 목적

- 동일한 업무 프로세스를 Make와 Zapier에서 각각 구현하여 자동화 플랫폼의 구성 방식과 기능적 차이를 비교·분석한다.
- 참가자 수 × 5개 레벨만큼 반복되는 "인증 확인 → 기록 → 축하 발송" 업무를 자동화하여 운영 시간을 단축하고, AI 기반 개인화 메시지를 업무 프로세스에 적용하는 것을 목표로 한다.

---

## 2. 프로젝트 Workflow

프로젝트에서 구현하는 Workflow는 다음과 같다. (구조는 Make와 Zapier에서 동일하게 구현)

1) Google Forms(미션 인증 제출) → 2) 응답 시트 신규 행 → 3) Trigger → 4) 검증(사진 첨부 Filter) → 5) 참가자 조회(트래커) → 6) Router/Filter(레벨 1~5 분기) → 7) Google Sheets 기록 → 8) Google AI(Gemini) 칭찬 생성 → 9) Discord 알림 → 10) 실행 로그 저장

---

## 3. Workflow 구성

Make, Zapier 두 플랫폼 모두 동일한 비즈니스 로직을 적용한다.

| 순서 | 기능 | 설명 |
|------|------|------|
| 1 | Trigger | 미션인증_응답 시트 신규 행 감지 |
| 2 | Filter | 인증 사진 첨부 여부 검증 (미첨부 → 재제출 안내 경로) |
| 3 | Action | 레벨업트래커에서 제출자 행 조회 (연결 키: 닉네임) |
| 4 | Filter/Router | 제출 레벨(Lv.1~5)에 따른 5갈래 분기 |
| 5 | Action | Google Sheets — 해당 레벨 완료 기록 (Update Row) |
| 6 | Action | Google AI(Gemini) — 순자 할매 사투리 칭찬 생성 |
| 7 | Action | Discord — 축하 + 다음 미션 안내 발송 (#미션달성) |
| 8 | Action | 실행 로그 저장 (운영로그 시트) |

## 4. Make 구현

### 1) 전체 Workflow

Google Sheets(Watch New Rows) → Router[사진 유무] → Router[레벨 1~5] → Google Sheets(Search Rows → Update a Row) → Gemini AI → Discord

### 2) Module 구성

| 순서 | Module |
|------|--------|
| 1 | Google Sheets — Watch New Rows (미션인증_응답) |
| 2 | Router — 사진 첨부 exist / notexist 분기 |
| 3 | Router — 레벨 선택 값(Lv.1~Lv.5) 5경로 분기 |
| 4 | Google Sheets — Search Rows (레벨업트래커에서 제출자 조회) |
| 5 | Google Sheets — Update a Row (LvN 상태=완료, Row number 매핑) |
| 6 | Google Gemini AI — Create a Completion (칭찬 코멘트 생성) |
| 7 | Discord — Create a Message (#미션달성) |
| 8 | (사진 미첨부 경로) Discord — 재제출 요청 메시지 |

### 3) Router 구성

```
Router(사진 exist)
 ┌── 경로1: 레벨 선택 = Lv.1 → 트래커 기록 → Gemini → Discord (Lv.2 안내)
 ├── 경로2: 레벨 선택 = Lv.2 → 트래커 기록 → Gemini → Discord (Lv.3 안내)
 ├── 경로3: 레벨 선택 = Lv.3 → 트래커 기록 → Gemini → Discord (Lv.4 안내)
 ├── 경로4: 레벨 선택 = Lv.4 → 트래커 기록 → Gemini → Discord (Lv.5 안내)
 └── 경로5: 레벨 선택 = Lv.5 → 트래커 기록(전체완료·인증서 미발급 도장) → 접수 안내
Router(사진 notexist)
 └── 오류 경로: Discord 재제출 요청 (DISCORD_RESUBMIT_REQUIRED)
```

### 4) Make 결과물

> 📸 (1) Make 전체 화면: Trigger부터 Router, Action까지 전체 구조 캡처 삽입
>
> 📸 (2) Trigger: Google Sheets Watch New Rows 설정 화면 캡처 삽입
>
> 📸 (3) Filter: 사진 첨부(exist/notexist) 조건 설정 화면 캡처 삽입
>
> 📸 (4) Router: 레벨(Lv.1~5) 경로별 필터 조건 화면 캡처 삽입
>
> 📸 (5) Google Sheets: Search Rows(닉네임 조회) + Update a Row(Row number 매핑) 설정 화면 캡처 삽입
>
> 📸 (6) Gemini AI: 프롬프트(순자 할매 페르소나) 설정 화면 캡처 삽입 — API Key 마스킹!
>
> 📸 (7) Discord: 채널 지정 및 메시지 템플릿 설정 화면 캡처 삽입

### 5) Make 구현 특징

- 시각적인 Flow — 5갈래 레벨 분기가 한 화면에 모두 보임
- Router 구현이 매우 직관적이며 무료 플랜에서 다중 분기 가능
- 모듈별 입출력 데이터를 History에서 버블 단위로 확인 가능 → 디버깅 용이
- 오류 경로(사진 미첨부)를 같은 시나리오 안에 함께 구성 가능

## 6. Zapier 구현

### 1) 전체 Workflow

Google Sheets(New Spreadsheet Row) → Filter(레벨 일치 + 사진 Exists) → Google Sheets(Lookup + Update Row) → Gemini → Discord

### 2) Module 구성

Zapier 무료 플랜은 다중 분기(Paths)가 유료이므로, 레벨별로 Zap을 분리하고 각 Zap의 Filter가 자기 레벨만 통과시키는 구조로 동일 로직을 구현하였다.

| Zap | Trigger | Filter | Action |
|-----|---------|--------|--------|
| Zap 1 (Lv.1) | Sheets — New Spreadsheet Row (미션인증_응답) | 레벨 = Lv.1 AND 사진 Exists | ① Lookup Row ② Update Row(Lv1=완료) ③ Gemini ④ Discord |
| Zap 2~4 (Lv.2~4) | 동일 | 레벨만 변경 | 동일 (레벨 숫자만 변경) |
| Zap 5 (Lv.5) | 동일 | 레벨 = Lv.5 AND 사진 Exists | ① Update Row(전체완료, 인증서 미발급) ② 접수 안내 |

### 3) Filter 구성

```
Zap별 Filter
 ┌── Zap1: 레벨 선택 = Lv.1 (그 외 전부 차단)
 ├── Zap2: 레벨 선택 = Lv.2
 ├── Zap3: 레벨 선택 = Lv.3
 ├── Zap4: 레벨 선택 = Lv.4
 └── Zap5: 레벨 선택 = Lv.5
```

### 4) Zapier 결과물 점검

> 📸 (1) Zap 전체 목록 화면 (레벨별 Zap 5개) 캡처 삽입
>
> 📸 (2) Trigger 설정 화면 캡처 삽입
>
> 📸 (3) Filter 조건 설정 화면 캡처 삽입
>
> 📸 (4) Google Sheets Update Row 설정 화면 캡처 삽입
>
> 📸 (5) Discord 메시지 설정 화면 캡처 삽입
>
> 📸 (6) Zap History 실행 로그 캡처 삽입

### 5) Zapier 구현 특징

- 개별 Zap의 UI는 단순하고 직관적 — 초보자 진입장벽 낮음
- 다중 분기(Paths)가 유료 → 무료 플랜에서는 Zap 5개로 분리해야 하며 관리 포인트 증가
- Zap History가 Zap 단위로 흩어져 있어 전체 흐름 추적은 Make보다 불편
- 월 100 Tasks 한도로 테스트 횟수에 제약 (참가자 1명 완주 ≈ 15 Tasks)

## 8. 플랫폼 비교 분석

### 1) Make

**장점**
- 라우터 하나로 5갈래 분기를 무료로 구현 — 본 과제 구조에 최적
- History에서 각 모듈의 입출력 버블을 단계별 확인 가능해 디버깅이 빠름
- 오류 경로(사진 미첨부)까지 한 시나리오 안에서 관리

**단점**
- Row number 매핑, exist/notexist 연산자 등 초기 개념 학습이 필요
- 모듈 수가 많아지면 Ops 소모 증가 (실행 1회당 약 5 Ops)

### 2) Zapier

**장점**
- 인터페이스가 단순해 개별 Zap은 몇 분 만에 완성
- 초보자도 쉽게 시작 가능

**단점**
- 다중 분기(Paths) 유료 → 레벨 5개 = Zap 5개로 분리, 동일 수정을 5번 반복해야 함
- 무료 100 Tasks/월 — 챌린지 참가자 6~7명 완주면 소진

### 3) 과금 체계 및 비용 효율성

- **Make (Operation 방식):** 모듈 1회 실행 = 1 Op. 본 워크플로우 1회 실행 시 약 5 Ops → 무료 1,000 Ops로 월 약 200건 인증 처리 가능.
- **Zapier (Task 방식):** 성공 Action당 1 Task. 1회 실행 시 약 4 Tasks → 무료 100 Tasks로 월 약 25건 처리. 5단계 레벨 구조에서는 과금 리스크가 큼.

## 9. 결론

동일한 미션 인증 워크플로우를 두 플랫폼에서 구현한 결과, **레벨 5단계 분기·오류 경로·AI 연동이 결합된 다단계 자동화에는 Make가 적합**했다. 라우터가 무료이고 실행 한도가 넉넉하며, History 기반 디버깅과 단일 시나리오 유지보수가 가능했기 때문이다. 반면 "폼 제출 → 알림 1건" 수준의 단선형 자동화라면 Zapier가 더 빠르고 직관적이었다. 이 비교 결과(분기 구현 방식, 무료 플랜 한도)를 근거로 프로젝트 2의 구현 도구로 Make를 선정하였다.

## 10. 트러블슈팅 및 예외 처리 (실제 발생 이슈)

### 1) Make — Update a Row의 rowNumber 누락 오류

- **발생 문제:** `필수 매개변수 'rowNumber'에 값이 누락되었습니다 (BundleValidationError)` 발생.
- **원인 분석:** Update a Row의 행 번호 칸에 Search Rows의 "Row number"가 아닌 다른 열 값(이메일주소)이 매핑되어 있었고, 해당 열이 비어 있어 검증에 실패함.
- **해결 방법:** 행 번호 칸에 Search Rows 출력의 Row number를 매핑하고, Search Rows와 Update 모듈 사이에 "Row number Exists" 필터를 추가해 미등록 제출 시 오류가 나지 않도록 보완.

### 2) Make — Gemini 출력이 칭찬 문구가 아님

- **발생 문제:** Gemini 모듈에 폼 답변 값만 나열되어 있어 출력이 의도한 칭찬 코멘트가 되지 않음.
- **해결 방법:** System Prompt에 "전라도 순천 72세 순자 할머니" 페르소나와 사투리·격려 규칙을 고정하고, User 메시지에는 "위 설명을 보고 2~3줄 칭찬만 출력" 지시문 + 폼 답변 매핑을 함께 구성.

### 3) Zapier — 다중 분기(Paths) 무료 플랜 제한

- **발생 문제:** 레벨 5갈래 분기를 Paths로 구성하려 했으나 유료 기능.
- **해결 방법:** 레벨별 Zap 5개로 분리하고 각 Zap의 Filter가 자기 레벨만 통과시키도록 재설계. 이 제약 자체를 비교 분석의 핵심 항목으로 반영.

### 4) 공통 — 중복 발송 방지 (멱등키)

- **설계:** Discord 발송 직전 운영로그 시트에 멱등키(`PASS|참가자ID|L레벨`)를 "처리중"으로 선점 → 이미 처리중/성공이면 차단 필터로 종료 → 발송 성공 후 "성공" 갱신. 트리거 중복 감지나 재실행 상황에서도 축하 메시지가 1회만 발송된다.
